## Overview

CricRelay is a live cricket broadcast platform. An operator uses the mobile app to stream a match via RTMP to YouTube or Twitch, while a scoreboard overlay (scraped from Play Cricket or entered via BLE scoring device) composites onto the video in real time. A Flask backend coordinates stream sessions, platform OAuth, overlays, and viewer stats.

**Viewer stats:** `StreamSession` accumulates `peak_viewers`, `viewer_sample_sum`, `viewer_sample_count` (→ `avg_viewers` property) for each broadcast session, linked to the `ClubUser` who started it via `started_by_user_id`. `final_score_json` and `vod_url` are stored at session end.

**Public-facing routes:** `/live/<slug>` — shareable no-login live-score page (polling or SSE when `PUBLIC_LIVE_SSE=1`). `/live/<slug>/events` — SSE push of score JSON (~1 s cadence; holds a gunicorn worker; keep `PUBLIC_LIVE_SSE` off until threaded workers or Redis pub/sub is in place). `/club/<slug>` — read-only org page for fans and sponsors. `/t/<slug>` — public tournament page (squads, schedule, fixture results, points table + NRR computed by `compute_points_table()`).

**Scoring migration flags:** `SCORING_DUAL_WRITE=1` shadow-writes each ball to `cricrelay_store` (Postgres event store) alongside the legacy engine. `SCORING_SHADOW_COMPARE=1` folds the event log through `cricrelay_core` on each `/score` read and logs divergences. Both failures are swallowed; the legacy engine stays authoritative until cut-over.

**Native mode models:** `Tournament` → `Team`/`Player` → `Fixture` supports non-ECB club-owned competitions. A `Fixture.score_match_slug` links to a `RelayMatch` for live scoring; `result_json` stores completed-game summary for NRR computation.

### 4. Live Overlay (`cricket_overlay.html`, `static/`, `templates/`)

Browser-rendered HTML/CSS/JS scoreboard burned into the stream via the camera engine's WebView compositor.

- Served by Flask at `/stream` and `/m/<slug>/stream` (rich overlay endpoint).
- **Design canvas:** 1280px reference layout (`DESIGN_W`); scales down when encode width is narrower (portrait 720p, low-tier 640p). Chrome at `/stream` is the visual reference at full 1280p.
- **Streamer phone:** Capture width tracks the **encoded RTMP frame** (not screen size). Orientation and encoder tier adjust automatically; strip stays bottom-anchored edge-to-edge on the video.
- **Viewer phone:** Overlay is burned into the video — Twitch/YouTube scale the whole frame. No per-viewer overlay layout; use 720p+ stream for readable text on phones.
- Receives score JSON via polling (`/score` or `/m/<slug>/overlay-data`).
- Team names are dash-formatted; T20 format is inferred pre-match.
- **Mobile capture/compositing (must match Chrome):**
  - Android `OverlayWebViewCapture`: rasterizes at **encoded canvas width** (dynamic, max 1280); injects viewport + top-pinned `#overlay` CSS via `measureScript()`; GL sprite composites at 100% width at default prefs. Theme class injected via `OverlayThemeBridge.applyThemeScript()` on every measure pass.
  - iOS `OverlayWebViewCapture`: same dynamic capture width + measure loop (2 s interval); `capture() async -> UIImage?` uses `webView.takeSnapshot(with: WKSnapshotConfiguration)` as primary rasterization (`snapshotWidth` = pixel-exact canvas width; WebKit renders out-of-process so `UIView.drawHierarchy` on an off-screen view returns blank on some OS versions); `layerTreeFallback(w:h:)` is the named explicit backup path; `StreamCameraEngine` scales and aligns via `OverlayLayout` geometry.
  - Overlay is now burned into the camera GL surface **during preview** (before Go Live) on both platforms via `StreamOverlayPolicy.PreviewGlRefresh` mode — operator sees WYSIWYG scoreboard in the preview.
- The `cricket_overlay.html` / `overlay_lovable_export.html` files are standalone variants for development.

**Studio module (`feature/studio`):**

`BroadcastCameraUi` — stateless Compose composable for the camera overlay:
- Separate `PortraitControls` and `LandscapeControls` layouts (detected via `BoxWithConstraints`).
- In portrait: tool row (Dest/Board/Score), then quick toggles row (Focus/Stabilize/Screen/Mic), then shutter row with pause button.
- In landscape: left rail = tool column (Dest/Board/Score vertically centered); right rail = quick toggle column (Focus/Stabilize/Screen/Mic) + Pause reveal + shutter (vertically centered, always visible and thumb-reachable).
- Both layouts share private composables (`ToolButtons`, `QuickToggles`, `PauseReveal`, `FocusReticle`, `StudioTopBar`, `StudioStatusMessages`, `ShutterLabel`) — identical control sets in both orientations, neither hides controls behind the other. `QuickToggles` contains four toggles: Focus Lock, Stabilize, Screen On, Mic Mute. The Stabilize toggle wraps its `CameraQuickToggle` in a `Column` that also renders `STABILIZATION_FOV_CAPTION` below the pill in portrait (non-vertical rail, `maxWidth 120dp`) **only when stabilization is at `CINEMATIC` level** — suppressed in the landscape vertical rail (caption + pill height was tall enough to push the Go Live shutter off-screen). The Stabilize pill is also **hidden entirely while streaming** (`if (!state.streaming)`) because stabilization cannot change mid-broadcast. **Pill labels**: `"Stabilize"` when off (UX intent is "tap to activate", not "currently off"), `"Standard"` at level 1, `"Cinematic"` at level 2; the string `"Off"` appears only in the accessibility `contentDescription` (`levelName.lowercase()`). iOS has no equivalent caption. The **Orientation** toggle button (ScreenRotation icon when Auto/unlocked; ScreenLockLandscape or ScreenLockPortrait when locked — three distinct icons, one per state) lives in `StudioTopBar` as a `CameraCircleButton` placed immediately after the Back button — hidden while streaming because the RTMP orientation is fixed once live. Tapping always flips to the opposite of the current physical display orientation (Landscape ↔ Portrait); `Auto` is never explicitly reached via the button. Placing it in the top bar means it never competes with the Go Live shutter rail for vertical space in landscape.
- Scoreboard and watermark burned into the camera GL surface (`StreamCameraEngine`) — no separate Compose overlay needed.
- Touch gestures: single-finger tap dispatches `onPreviewTap` for focus; two-finger pinch dispatches `onPinchZoom` via `rememberTransformableState` (same as iOS `CameraPreviewView`).
- `onShare: (() -> Unit)?` callback — when non-null and streaming, the top-bar Menu button is replaced by a Share button (animated crossfade via `AnimatedContent`). Built from `state.watchUrl` in `StudioScreen` and dispatched via `Intent.ACTION_SEND`.
- Haptic feedback: `LaunchedEffect(state.streaming)` fires `haptic.performHapticFeedback(HapticFeedbackType.LongPress)` when streaming starts — tactile confirmation to the operator at the moment the RTMP broadcast connects.
- `StreamStatsBadge` private composable — shown below the `LiveTimerBadge` in `StudioTopBar` when `state.streamStats != null` (i.e. while streaming). Renders quality label (`NNNpFPS`), live Mbps (`%.1f`), and a tri-color 7dp dot: green=stable (target ≥ 90% of max, not congested), amber=adapting (target < 90%), red=congested (RTMP send cache backing up). Full accessibility `contentDescription` ("Streaming NNNp at X.X megabits per second, stable/adapting/congested").
- Thermal warning banner (`THERMAL_STATUS_SEVERE`) with "Lower quality" action (`THERMAL_STATUS_CRITICAL`).
- Reconnect banner: when `state.reconnecting`, `StudioStatusMessages` renders an amber pill with a 16dp `CircularProgressIndicator` (warning color, 2dp stroke) and "Connection lost — reconnecting…" text; auto-clears when the engine reconnects (`EVENT_CONNECTED`) or the user stops the broadcast.
- When `state.arrangeMode == true`, `StudioScreen` renders `ArrangeOverlay` (separate file `ArrangeOverlay.kt`) as a full-screen Compose overlay above the camera preview; `BroadcastCameraUi` itself becomes non-interactive during Arrange.

`StudioViewModel` owns broadcast state and orchestrates the full go-live flow:
- *Camera gate*: `StudioCameraGate.Readiness` (match loaded + permissions + surface bound) guards `prepareCamera()` — no partial starts.
- *Overlay preview*: `streamController.setPreviewOverlayListener` (legacy path retained) and `syncOverlay()`/`syncSponsorLayer()` push overlay to GL on preview; WYSIWYG preview via `PreviewGlRefresh` mode. `previewOverlayPrefs()` pushes overlay/sponsor changes live without persisting to the server; `revertOverlayPreview()` restores the last saved prefs on sheet dismiss.
- *Arrange mode*: `StudioUiState` carries `arrangeMode: Boolean`, `arrangeTarget: ArrangeTarget` (`Board`/`Sponsor`), `arrangeDraft: OverlayLayoutPrefs?`. `enterArrangeMode()` opens Arrange, closes sheets, seeds the draft from saved prefs. `pinchBoard(zoom)` calls `OverlayLayoutPrefs.withBoardScale()` (aspect-locked); `dragArrange(dxFraction, dyFraction)` updates `anchorX`/`bottomMargin` (Board) or `sponsorPositionX/Y` (Sponsor). All changes go to `previewOverlayPrefs()` (GL only, no network); `commitArrangeMode()` persists once via `updateOverlayPrefs()` and advances precheck to `PrecheckStep.Ready`.
- *First-run precheck (Android)*: `PrecheckStep` enum (`Camera`/`Arrange`/`Ready`). `StudioUiState` carries `precheckActive: Boolean`, `precheckStep: PrecheckStep`. `revealStudio()` sets `precheckActive = !it.streaming && !rtmpStore.isPrecheckDone()`. `precheckStartArrange()` calls `enterArrangeMode()` while keeping precheck active. `finishPrecheck()` calls `rtmpStore.setPrecheckDone()` and clears `precheckActive`. `requestGoLive()` returns early when `state.precheckActive`. Precheck auto-dismisses when a live broadcast starts (`precheckActive = it.precheckActive && !status.streaming`). `StudioScreen` renders `PrecheckCard` (separate composable, `PrecheckCard.kt`) when `state.precheckActive && !state.arrangeMode && state.goLiveCountdown == null`.
- *PiP mode*: `streamController.pipMode` Flow collapses the UI to camera-only and closes sheets when entering PiP.
- *Go-live flow*: `requestGoLive()` → preflight sheet → `confirmGoLive()` → 3-2-1 countdown → `goLive()`. OAuth platforms call `streamRepository.goLive(slug, platform)` to get RTMP creds from the server; custom RTMP uses `RtmpCredentialsStore` (SharedPrefs, keyed by slug).
- *Broadcast sync*: `updateBroadcastStatus()` pushes streaming/paused/idle state back to server bidirectionally.
- *Focus/zoom*: `tapToFocusAt()` + `lockFocus()`/`unlockFocus()` mirrored from `StreamController`; focus reticle dismissed after 1.5 s unless locked. `onPinchZoom(scale)` multiplies the current zoom level and calls `setZoom()`.
- *Orientation mode*: `OrientationMode` enum (`Auto`/`Landscape`/`Portrait`) added to `StudioUiState`. `toggleOrientation(currentlyLandscape: Boolean)` flips to the opposite of the current display orientation (Portrait→Landscape or Landscape→Portrait; no-op while streaming). `Auto` is the default starting state (physical auto-rotate) but is never explicitly reached via the button — only restored on Studio dismiss. On each toggle, calls `streamController.clearDeviceOrientation()` so the engine re-derives from the about-to-be-locked display and sets `statusMessage` with a contextual hint ("Landscape — tap again for portrait" / "Portrait — tap again for landscape"). `StudioScreen` drives `activity.requestedOrientation` via `LaunchedEffect(state.orientationMode)` (`SCREEN_ORIENTATION_SENSOR_LANDSCAPE` / `SCREEN_ORIENTATION_PORTRAIT` / `SCREEN_ORIENTATION_UNSPECIFIED`) and resets to `UNSPECIFIED` on dispose.
- *Lifecycle hooks*: `onStudioVisible()` and `onConfigurationChanged()` both call `streamController.refreshNativePreview()`; `StudioScreen` fires `onStudioVisible()` 5× via `LaunchedEffect(Unit)` (once immediately then 4× at 150 ms intervals) as a startup surface-elevation retry that ensures Compose is above the camera GL surface from the first frame — and fires it again 4× at 200 ms intervals via `LaunchedEffect(state.streaming)` the moment streaming starts, keeping Compose above the camera SurfaceView during the RTMP connection window; `onDeviceOrientationChanged(surfaceRotationDegrees)` relays sensor rotation to `streamController.setDeviceOrientation()` — **only when `orientationMode == OrientationMode.Auto`** (locked interface is the truth under a lock, so the sensor is ignored); `onStudioHidden()` sets `previewSurfaceBound = false` and calls `streamController.hideNativePreview()` (complement to `onStudioVisible()`). `StudioScreen` registers an `OrientationEventListener` with `SensorManager.SENSOR_DELAY_NORMAL` and maps raw degrees → Surface.ROTATION_* before dispatching to `onDeviceOrientationChanged()`.
- *Match-day polling*: 8-second coroutine loop via `streamRepository.getMatchDayStatus()`.
- *Scoring mode*: `setScoringMode()` supports `"auto"`, `"manual"`, `"auto:cricheroes"` (provider prefix stripped before API call).
- *Local-first prefs*: `StudioLocalPrefsStore` (injected) is read in `loadStudioExtras()` before any server call — `loadOverlayPrefs(slug)` serves the cached overlay prefs if present; server fetch only runs to seed a fresh install, and the result is immediately persisted locally. `loadDeviceSettings().appliedTo(basePrefs)` merges device camera settings (stabilization, keepScreenOn) over the overlay prefs. `saveDeviceSettings()` is called whenever a quick toggle changes stabilization level or keep-screen-on.
- *Go Live quality selection*: `autoSelectGoLiveQuality()` runs just before RTMP connect on HIGH-tier devices; measures upload speed via `streamRepository.measureUploadMbps()` (2 MB probe, 8 s timeout), then calls `GoLiveQualityPolicy.choose()` and `streamController.ensurePreparedQuality()` to re-prepare at the appropriate quality (1080p vs 720p) without full teardown.
- *Broadcast health*: `streamController.streamStats` Flow collected in `init`; forwarded to `StudioUiState.streamStats` so `BroadcastCameraUi.StreamStatsBadge` can render live quality/bitrate/congestion state.
- *Stream cache*: `StreamDao` provides instant local match data while remote fetch completes (12 s timeout fallback).
- *Mid-broadcast reconnect*: `StudioUiState.reconnecting: Boolean` is set on `EVENT_RECONNECTING` (engine is retrying autonomously, broadcast is still live — amber banner, no action required); cleared on `EVENT_CONNECTED` or when `status.streaming` becomes false. `EVENT_STREAM_LOST` triggers `onStreamLost(detail)` — cancels the live timer, calls `streamController.onStreamLost()`, resets `streaming/paused/busy/reconnecting` to false and `liveElapsedSeconds` to 0, surfaces "Broadcast lost: {detail}. Check signal and Go Live again." error banner, fire-and-forgets `updateBroadcastStatus(idle)` to the server. `EVENT_OVERLAY_WARNING` and `EVENT_KEEPALIVE_WARNING` both set `error = event.message` without touching `streaming` (burn-in degraded / keep-alive FGS unreachable respectively — broadcast continues, operator warned to keep screen on if FGS is down). `reconnecting = it.reconnecting && status.streaming` guard clears the amber banner automatically if the user manually stops during a reconnect window. Focus-lock engine-truth sync: `focusLocked = streamController.isFocusLocked()` on every engine status update (prevents the padlock UI drifting after a re-prepare or rotation that calls `resetFocusState()` inside the engine).
- *Remote companion*: `startRemoteCommandPolling()` polls every 1.5 s; `handleRemoteCommands()` dispatches `control` (start_broadcast, stop_broadcast, mute_mic, toggle_focus_lock, toggle_sponsor) and `overlay` (sponsor patch via `RemoteCommand.mergeSponsorInto()`). `createPairingCode()` builds the `cricrelay://pair?…` deep-link payload.
- *Mic mute*: `onToggleMicMuted()` → `streamController.setMicMuted(next)`.
- *Thermal*: `thermalStatus` from `StreamCameraEngine` status events; `onLowerQuality()` → `streamController.stepDownQuality()`.
- *Sponsor layer*: `syncSponsorLayer()` resolves logo URLs from `Sponsor` list and calls `streamController.updateOverlay()` or `streamController.setSponsorLayer()` depending on whether an overlay URL is present.
- *Recap*: on stop, builds a `StreamRecap` and surfaces it.

**`RtmpCredentialsStore.kt`** (Android) — SharedPreferences persistence for custom RTMP URL / stream key / watch URL, keyed by match slug (Hilt `@Singleton`). Adds `isPrecheckDone(): Boolean` and `setPrecheckDone()` using SharedPrefs key `"studio_precheck_done"` — the Android persistence layer for the first-run guided precheck. Also hosts the Android adapter layer via Kotlin extension functions: `OverlayLayoutPrefs.toEngineLayout(sponsorLogoUrls)` converts the full KMP domain prefs to `StreamCameraEngine.OverlayLayout` (all board, sponsor, scroll, watermark, and opacity fields); `OverlayLayoutPrefs.bottomMarginPx(frameHeightPx)` converts the raw `bottomMargin` double to physical pixels via `(bottomMargin / 720f).coerceIn(0f, 0.2f) * frameHeightPx`. The iOS equivalent adapter is `OverlayLayoutPrefs.toEngineLayout()` defined in `Models.swift`.

**`StudioLocalPrefsStore.kt`** (Android, new file) — local-first persistence for studio setup, Hilt `@Singleton`. Backed by `SharedPreferences` file `"cricrelay_studio_prefs"`. Two-tier design: (1) **Device settings** (`DeviceStreamSettings` data class: `stabilizationLevel: Int`, `keepScreenOn: Boolean`) stored per-device with `loadDeviceSettings()` / `saveDeviceSettings()` (keys `device_stabilization_level`, `device_keep_screen_on`) — never read from the server; a club admin editing the web dashboard has no business changing this phone's EIS mode. (2) **Overlay prefs** cached per match slug with `loadOverlayPrefs(slug)` / `saveOverlayPrefs(slug, prefs)` (key `overlay_prefs_<slug>`) — the cache is authoritative for the studio; the server copy only seeds a fresh install and is the mirror the web dashboard + remote companion read. `DeviceStreamSettings.appliedTo(prefs: OverlayLayoutPrefs)` overlays device camera settings onto match overlay prefs (merges `stabilizationLevel` + `keepScreenOn`). iOS parity: `DeviceStreamSettings` struct + `StudioLocalPrefsStore` enum added to `RtmpCredentialsStore.swift`, same two-tier design backed by `UserDefaults`.

**`GoLiveQualityPolicy.kt`** (Android, new file) — upload-probed quality selection. `choose(deviceSupports1080: Boolean, measuredMbps: Double?)` → `FULL_HD` (`Choice(1920, 1080, 4_500_000)`) when device is HIGH tier AND measured upload ≥ `MIN_MBPS_FOR_1080P = 6.0` Mbps; → `HD` (`Choice(1280, 720, 2_500_000)`) when measured < 6 Mbps; → `null` (keep current prepared quality without re-preparing) when probe returned null (probe unavailable or server too old). Wired into `StudioViewModel.autoSelectGoLiveQuality()` which runs just before Go Live on HIGH-tier devices: calls `streamRepository.measureUploadMbps()` (2 MB probe, 8 s timeout), passes the result to `GoLiveQualityPolicy.choose`, then calls `streamController.ensurePreparedQuality(choice.width, choice.height, choice.bitrateBps)` to re-prepare at the chosen quality without a full teardown.

- `shouldAttachGlOverlayOnPreview` / `shouldAttachGlOverlayOnStream` helpers.
- Overlay burns into GL during preview (not only stream) so WYSIWYG holds.
- `StreamOverlayPolicyTest` covers all `refreshMode` branches and both `shouldAttach*` helpers.
- `OverlaySpriteLayoutTest` covers `computePosition` (bottom-flush, margin lift, bounds), `fitScale` (aspect preservation under pinch, portrait overflow clamp), and `shouldForceTransparentBackground` (Compose host detection) — 10 test cases total.
- `OverlayLayoutPrefsArrangeTest` (`feature/studio`) covers board-scale bounds (`withBoardScale` clamp), drag-clamping for `anchorX`/`bottomMargin` mutations, and anchor-update helpers exercised by Arrange mode interactions.
- `OverlayLayoutPrefsTest` (`shared/commonTest`) covers `effectiveFontScale` independence from board size, `boardDisplayScaleX/Y`, `toJson` writing both `stabilization_level` (int) and `video_stabilization` (bool), `fromJson` preferring the int level over the legacy bool and falling back to the bool when the int field is absent, `withStabilizationLevel` sanitizing out-of-range values while keeping `videoStabilization` in sync, fresh-prefs defaults (Floodlight board + bowling island on), `sanitizeTheme` accepting all 6 preset ids (case/whitespace tolerant) and falling back to `"floodlight"` for unknown/null/blank input, `BoardPreset.ALL` catalogue display-name ordering, and `BoardPreset.byId` resolver.
- `ModelsJsonTest` (`shared/commonTest`) — comprehensive JSON round-trip tests for all wire models: `BroadcastStatus` (null-safe defaults, `isStreaming`/`isPaused` computed flags, kotlinx round-trip); `StreamMatch` (full server payload, legacy `"paused"`/`"live"` field aliases, relative-vs-absolute `overlay_embed_url` resolution against `baseUrl`, kotlinx round-trip); `OverlayLayoutPrefs` (full-field `toJson`/`fromJson` round-trip, kotlinx `@SerialName` wire-key round-trip, single `active_sponsor_id` promoted into `activeSponsorIds` list, out-of-range sponsor values clamped + invalid mode strings sanitized, all 6 board preset ids preserved, `barlow` legacy id preserved, missing theme defaults to `"floodlight"`, bowling island flag, blank watermark text falls back to default, sponsor patch merge touches only sponsor keys not board fields, sponsor patch JSON key coverage).

`OverlayThemeBridge` — theme name → HTML/CSS mapping:

- `urlWithTheme(url, theme)` → appends `?theme=<theme>` query param.

`AgentDebugLog` — structured debug instrumentation (location/message/data map/hypothesisId/runId). Used in `BroadcastCameraUi`, `StudioViewModel`, `StreamCameraEngine`, `OverlayWebViewCapture`.

`StreamController` — native streaming facade (`@Singleton`, Hilt). Adds `setDeviceOrientation(surfaceRotationDegrees: Int)` and `clearDeviceOrientation()` pass-throughs to `StreamCameraEngine` (alongside the existing `setPreviewOverlayListener`, `updateOverlay`, `startStream`, focus, zoom, sponsor, and quality methods). `setStabilizationLevel(level: Int)` is the primary stabilization API; `setVideoStabilization(enabled: Boolean)` is a back-compat shim that maps to `setStabilizationLevel(if (enabled) 1 else 0)`. `setPipMode(active: Bool)` drives `_pipMode: StateFlow<Boolean>`. `_streamStats: MutableStateFlow<StreamStats?>` (fed by `StreamCameraEngine.setStatsListener`); `streamStats: StateFlow<StreamStats?>` (null when not live) is collected by `StudioViewModel` and forwarded to `StudioUiState.streamStats`. `supports1080p()` returns `StreamCameraEngine.supports1080p()` (true when device tier is HIGH). `ensurePreparedQuality(width, height, bitrateBps)` re-prepares the encoder at an explicit quality before Go Live — no-op if already at that quality, pre-stream only. `onStreamLost()` — reconnect-exhausted path: stops the foreground `StreamCaptureService` and re-syncs `_status` to `streaming=false, paused=false` WITHOUT calling `StreamCameraEngine.stopStream()` (engine already tore itself down when retries ran out; calling stop again would crash). **FGS resilience**: private `startForegroundService(act)` now logs "Go Live keep-alive start refused — engine will re-assert on connect" when `StreamCaptureService.start()` returns false (OS refused — `ForegroundServiceStartNotAllowedException` on 12+ when backgrounded); it does NOT throw so a remote Go Live from background still connects RTMP, and `ensureKeepAliveService()` on `onConnectionSuccess()` is the recovery path. Private `stopForegroundService()` uses the saved `appContext` (survives `detachActivity`) so the service can be stopped even after the Activity is gone. **`startStream()` quality params are defaults, not runtime selectors**: signature is `startStream(rtmpUrl, streamKey, overlayUrl, layout, width: Int = 1280, height: Int = 720, bitrateBps: Int = 2_500_000, fps: Int = 30)`; `StudioViewModel.goLive()` never passes the optional quality params — it relies on `ensurePreparedQuality()` having already set quality at prepare time; the engine stores the passed params but does not use them to re-prepare when already prepared. Quality is always determined by `preparePreview()`/`ensurePreparedQuality()`, not by `startStream()`.

`DeviceCapabilities` — pure static object. `tier(context)` returns LOW/MID/HIGH from `isLowRamDevice` + `totalMem` (<3 GB=LOW, <6 GB=MID, ≥6 GB=HIGH). Drives: `defaultStreamWidth/Height` (HIGH=1920×1080, others=1280×720), `defaultStreamBitrate` (HIGH=4_500_000, others=2_500_000), `overlayRefreshMs` (LOW=1200, MID=800, HIGH=500), `maxOverlayCaptureWidth` (LOW=640, MID=1280, HIGH=1920), `suggestedQualityId`, `defaultEisEnabled` (false on LOW), `isPowerSaveMode`, `isThermalStressed`, `toMap`. `StreamCameraEngine` calls `refreshDeviceTier()` on `attachView` and when adjusting for power-save/thermal; `deviceTier` starts at MID until the first `attachView` measures the device. `supports1080p()` returns `deviceTier == HIGH`.

`StreamCameraEngine` — RootEncoder 2.4.8 RTMP engine singleton:
- **Phase state machine**: `phase: StreamPhase` (default `Idle`) is the single source of truth; `encoderPrepared: Boolean`, `streamPaused: Boolean`, and `backgroundRendering: Boolean` are computed properties derived from it. `applyIntent(intent: StreamPhasePolicy.Intent): Boolean` validates every transition — a refused intent (returns `false`, logs warning) leaves the phase and all derived state untouched rather than corrupting flags. Critical guards: `Prepare`/`Release` refused while `Live` (known Pixel mid-stream re-prepare crash + stale surface-loss callback race); `Stop` always legal (idempotent below Live).
- `StreamStats` data class (inner): `sentBitrateBps`, `targetBitrateBps`, `maxBitrateBps`, `width`, `height`, `fps`, `congested`, `droppedVideoFrames` — published ~1/sec via `setStatsListener`; null between streams. `BitrateAdapter` (RootEncoder) is created at RTMP connect and fed by `onNewBitrate`; calls `cam.setVideoBitrateOnFly` to track the real network capacity up/down. `currentTargetBitrate` tracks the adapter's current bitrate; `adapting = currentTargetBitrate < maxBitrateBps * 0.9f`; `congested` when RTMP send cache is backing up. `setStatsListener(((StreamStats?) -> Unit)?)` lets `StreamController` subscribe.
- `OverlayLayout` data class carries all scoreboard + sponsor GL parameters: `heightFraction`, `widthFraction`, `anchorX/Y`, `bottomMarginFraction`, `horizontalInsetFraction`, `fontScale`, `bgColor`, `textColor`, `opacity`, `watermarkEnabled/Text`, `sponsorEnabled`, `sponsorLogoUrl`, `sponsorLogoUrls` (up to 6), `sponsorLayoutMode` (single/multi/carousel), `sponsorCarouselIntervalSec`, `sponsorDisplayMode` (static/scroll_*), `sponsorPositionX/Y`, `sponsorSizeScale`, `sponsorOpacity`, `sponsorScrollSpeed`, `sponsorScrollDirection` (ltr/rtl/ttb/btt/fixed), `theme`.
- **Camera abstraction**: `private var camera: CameraSession?` — engine holds a `CameraSession` interface, not a concrete `RtmpCamera2`. Created in `attachView()` as `RtmpCameraSession(view, this)`. `SponsorLayer` and `OverlayCompositor` receive their `camera` lambda as `() -> CameraSession?` — neither module depends on the RootEncoder type directly.
- **Scoreboard burn-in**: delegated entirely to `private val overlayCompositor: OverlayCompositor`. The compositor owns the `OverlayWebViewCapture`, the GL filter (`overlayObject`), the preview and stream refresh loops, the bitrate-aware capture width, and the `boardBand()` geometry tracker. `StreamCameraEngine` calls compositor methods at each lifecycle boundary: `syncOverlayCaptureWidth()` after prepare, `applyOverlayConfig()` after `updateOverlay()`, `startOverlayRefresh()` / `stopOverlayRefresh()` on stream start/stop/pause/resume, `reattachAfterSwap()` after offscreen-GL swaps, `destroyOverlayCapture()` on full teardown. `ensureSiblingBurnIns` lambda passed at construction re-attaches watermark + sponsor after each composite cycle.
- **Board-scale GL compositing**: `OverlayCompositor.applyOverlaySprite()` uses `OverlaySpriteLayout.fitScale()` to compute a uniform aspect-locked scale from `widthFraction / REF_OVERLAY_WIDTH_FRACTION`, then `OverlaySpriteLayout.computePosition()` for position — the overlay strip never distorts regardless of pinch. Updates `boardTopPct`/`boardBottomPct` from the result, exposed via `boardBand()`. This replaces ad-hoc width/height multipliers; method moved from `StreamCameraEngine` to `OverlayCompositor`.
- Sponsor compositing: delegated to `SponsorLayer` (same package). `SponsorLayer` receives engine state through constructor lambdas (`mainHandler: Handler`, `camera: () -> CameraSession?`, `appContext`, `layout`, `canvasSize`, `boardBand`, `applyOpacity`, `warn`) and manages `Slot` objects (each wrapping an `ImageObjectFilterRender`); logos are fetched on a single-thread executor with on-disk cache; carousel and scroll timers run on the main handler. `StreamCameraEngine` calls `sponsorLayer.ensure()` after every prepare / filter-rebuild event and `sponsorLayer.dropStaleRefs()` whenever the GL chain is torn down. `boardBand` lambda reads `overlayCompositor.boardBand()` — board tracking (`boardTopPct`/`boardBottomPct`) moved to `OverlayCompositor` with `applyOverlaySprite()`; above/below-board display modes still track the real board position.
- **Sponsor scroll direction**: now owned by `SponsorLayer`. Scroll constants (`SCROLL_FRAME_MS=33L`, `SCROLL_STEP_PCT=0.45f`, `SCROLL_GAP_PCT=8f`, `SCROLL_WRAP_PCT=100_000f`), direction constants (`SCROLL_DIR_LTR/RTL/TTB/FIXED`), `scrollAxisHorizontal()`, private `applySprite(filter, slot, index, total)`, `scrollActiveDir`, `startScroll()`, `marqueePhase(period, index, total)` all live in `SponsorLayer`. `StreamCameraEngine` delegates entirely via `sponsorLayer.ensure()` / `sponsorLayer.dropStaleRefs()`.
- Watermark: `ensureWatermarkFilter` builds/caches a bitmap pill and positions via `WatermarkSpriteLayout.compute()`. `WatermarkSpriteLayout`'s geometry constants (`HEIGHT_PCT`, `RIGHT_EDGE_PCT`, `TOP_PCT`, `MAX_WIDTH_PCT`, `BMP_HEIGHT`) are `internal` and shared with `SponsorLayer` so both burn-in layers respect the same crop-safe zone.
- Thermal: delegated to `ThermalMonitor` (new file, same package). `thermalMonitor.register(context)` / `unregister(context)` called from `attachView()` / `releaseCamera()`; status changes delivered to `onThermalStatusChanged(status: Int)` which adapts `overlayRefreshMs` (moderate: ×1.5, severe: ×2.5 capped at 3.5 s) and emits `"thermal"` status events.
- Background resilience: `onEnterBackground()` → `cam.replaceView(ctx)` swaps encoder to offscreen GL interface so broadcast survives screen lock; `onExitBackground()` → `replaceView(openGlView)` restores on-screen rendering; `reattachBurnInsAfterSwap()` re-attaches filters after each GL swap.
- **RTMP self-heal reconnect**: `reconnectAttempt: @Volatile Int` armed at Go Live (`cam.setReTries(StreamReconnectPolicy.MAX_ATTEMPTS)` = 3 attempts via `CameraSession` interface), reset to 0 at each stream start. `onConnectionFailed(reason)` calls `cam.reTry(delayMs, reason)` with `StreamReconnectPolicy.backoffMs(reconnectAttempt)` (1s/2s/4s, cap 8s); if `reTry` succeeds → `reconnectAttempt++` + emits `EVENT_RECONNECTING`; if `reTry` returns false (budget exhausted or non-retryable endpoint) → calls private `endLostStream(detail)`. `endLostStream(detail)` combines `stopStreamInternal()` (re-prepares preview from scratch) + `emit(EVENT_STREAM_LOST, detail)` — the single teardown path for both retry exhaustion and auth failure. `onConnectionSuccess()` resets `reconnectAttempt = 0`, refills `camera?.setReTries(MAX_ATTEMPTS)` (so a later outage in the same broadcast still gets the full 3-attempt budget), creates a fresh `BitrateAdapter`, and emits `EVENT_CONNECTED` (with message "Reconnected" when `wasReconnect`). `onAuthError()` — no retry: calls `endLostStream("Stream key rejected. Start the live event in Studio/dashboard first, then try again.")` immediately; platform-rejected stream keys must not be retried (the rejection is permanent until the operator creates the live event). `burnInWarned.clear()` at stream start so a new broadcast gets fresh single-fire warnings.
- **Burn-in degradation warnings**: `burnInWarned: MutableSet<String>` tracks keys already warned this broadcast. `warnBurnInOnce(key, message)` emits `EVENT_OVERLAY_WARNING` exactly once per key per broadcast (called from `ensureWatermarkFilter` on watermark filter-attach error and from `SponsorLayer.createSlot` on sponsor filter-attach error). Overlay-capture streak tracking (`overlayCaptureFailStreak` / `OVERLAY_CAPTURE_WARN_STREAK=8`) moved to `OverlayCompositor`. **Keep-alive FGS guard**: `ensureKeepAliveService()` (public) checks `StreamCaptureService.isForegroundActive` and re-starts the service if it's down while streaming; called from `onConnectionSuccess()` (every RTMP connect/reconnect) and `onExitBackground()` (every foreground return) — the two moments where `startForegroundService` is guaranteed safe. A `KEEPALIVE_VERIFY_MS = 4_000L` deferred check re-triggers `warnKeepAliveOnce()` if the service is still not active after the async start. `keepAliveWarned: Boolean` reset at stream start (alongside `burnInWarned.clear()` and `reconnectAttempt = 0`); `warnKeepAliveOnce()` emits `EVENT_KEEPALIVE_WARNING` exactly once per broadcast.
- Memory pressure: `onMemoryPressure()` pauses overlay capture; `onMemoryRestored()` resumes.
- Mic mute: `setMicMuted(muted)` calls `cam.disableAudio()` / `cam.enableAudio()`.
- Step-down quality: `stepDownQuality()` stub (TODO: RootEncoder live-bitrate API).
- **Video fallback tiers**: `buildVideoFallbackTiers()` steps through up to 4 resolutions when `prepareVideo` fails at the requested tier — `1280×720@2.5Mbps` → `854×480@1.5Mbps` → `640×360@24fps@800kbps` — so broadcast can start on budget devices without a hard failure.

- **Orientation sensor integration**: `sensorSurfaceRotation: Int = -1` stores the last valid sensor surface-rotation degree from `StudioViewModel`. `currentSurfaceRotation()` returns the sensor value when valid (0/90/180/270), otherwise falls back to the display rotation from `displayRotationDegrees(act)`. `setDeviceOrientation(surfaceRotationDeg)` stores the value (normalises; ignores out-of-range), then calls `updatePreviewRotation()` on the GL thread unless streaming. `clearDeviceOrientation()` resets `sensorSurfaceRotation = -1` and re-prepares from the display rotation so the encoder re-aligns with the locked interface.

Note: Android has focus-only lock (RootEncoder 2.4.8 has no AE-lock API); iOS locks both focus and exposure. Stabilization: Android `setStabilizationLevel(level)` — OFF (no EIS/OIS), STANDARD (`enableVideoStabilization()` + OIS), CINEMATIC (`Camera2Controls.setEisMode(cam, 2, live)` sets `PREVIEW_STABILIZATION=2` via builder reflection, degrades to EIS 1 if reflection unavailable). iOS `StreamCameraEngine.setStabilizationLevel(Int)` — same 0/1/2 range. Cinematic narrows the camera's FOV (noted in the `STABILIZATION_FOV_CAPTION` below the Android quick-toggle pill).

| Decision | Detail |
|----------|--------|
| **Freemium tiers** (June 2026) | AdMob on free tier; custom sponsor overlay slot as Pro upsell; `Sponsor.active_from`/`active_to` bound sponsorships by date; website is the acquisition layer |

| **Scoring dual-write / shadow** | `SCORING_DUAL_WRITE` + `SCORING_SHADOW_COMPARE` env flags wire the new `cricrelay_core`/`cricrelay_store` engine in shadow mode; legacy engine stays authoritative until explicit cut-over |

| **3-level stabilization** | `StabilizationLevel` KMP object: `OFF=0` (EIS+OIS disabled), `STANDARD=1` (EIS on + OIS — previous behaviour), `CINEMATIC=2` (strongest EIS grade via Camera2 `PREVIEW_STABILIZATION=2` on Android / AVFoundation `cinematicExtended` on iOS, plus OIS — narrows FOV, operator opts in). `OverlayLayoutPrefs.stabilizationLevel` is the persisted source of truth; `videoStabilization: Boolean` is kept in sync as a wire-compat field for old server/client readers. Android CINEMATIC path uses `Camera2Controls.setEisMode()` builder reflection and degrades to EIS 1 if unavailable. |
| **Broadcast resilience** | Android: RootEncoder `replaceView` offscreen-GL swap + PiP overlay keeps stream alive on locked screen. iOS: background task + standby slate (branded full-frame card composited over frozen camera via `ImageScreenObject`); audio session stays active under UIBackgroundModes audio. Pause (both platforms): full-frame black overlay + audio mute — Android uses `BlackFilterRender` + `cam.disableAudio()`; iOS uses `pauseBlackObject: ImageScreenObject?` (`showPauseBlackOverlay()` / `hidePauseBlackOverlay()`) + `mixer.attachAudio(nil)` + `AVAudioSession.setActive(false, .notifyOthersOnDeactivation)` so commentary cannot leak over the slate; `resumeStream()` restores the audio session and re-attaches audio respecting `micMuted`. |
| **Overlay in preview (WYSIWYG)** | `StreamOverlayPolicy.PreviewGlRefresh` mode burns the scoreboard into the camera GL surface before Go Live. On Android, the GL filter chain is active during preview; on iOS, `ensureOverlayObject` + `startOverlayRefresh` run from `preparePreview`. The operator sees exactly what viewers will see. |
| **Arrange mode (Android + iOS)** | Pre-live direct manipulation of the board and sponsor position — now shipped on both platforms. `enterArrangeMode()` seeds a draft from saved prefs; pinch calls `withBoardScale()` (aspect-locked, 0.4×–1.0×); drag moves `anchorX`/`bottomMargin` (Board) — `BOARD_DRAG_MARGIN_SPAN=400.0` maps drag fraction to raw-pixel board lift, capped at `BOARD_DRAG_MARGIN_MAX=400.0` (same span on iOS: `min(400, max(0, p.bottomMargin - dyFraction * 400))`) — or `sponsorPositionX/Y` (Sponsor). All changes push to GL preview via `previewOverlayPrefs()` with no network call; `commitArrangeMode()` persists once on Done and advances the first-run precheck to its final step. Android: `ArrangeOverlay.kt` composable. iOS: `ArrangeOverlayView` SwiftUI struct with `MagnificationGesture` + `DragGesture`. |
| **First-run guided precheck** | On first Studio launch (before any Go Live), operators see a 3-step stepper: Camera → Arrange → Ready. `PrecheckStep` enum drives the step on both platforms. Precheck is dismissed automatically when the operator taps "All set" / "Skip" (`finishPrecheck()`) or when a live broadcast starts (Android auto-dismiss). `requestGoLive()` blocks while `precheckActive`. Completion is persisted: Android — `RtmpCredentialsStore.setPrecheckDone()` (SharedPrefs key `"studio_precheck_done"`); iOS — `UserDefaults` key `"cricrelay.studio.precheck_done"`. |
| **Multi-preset overlay themes** | `OverlayLayoutPrefs.sanitizeTheme()` accepts 6 board preset ids: `"floodlight"` (default — Floodlight-era dark ink + gold), `"chalk"` (light parchment + club green), `"club-green"` (pitch green + gold), `"broadcast-blue"` (navy + sky), `"mono"` (black + white). Legacy `"barlow"` Classic board is kept for existing users (`BoardPreset.legacy=true` — preset pickers show it last). `BoardPreset` KMP data class provides display names + CSS swatch colours (row-1 background + accent) for preset picker rendering on both platforms. Unknown/blank ids fall back to `"floodlight"`. Prior non-preset theme strings (classic/neon/minimal/compact/ai/stadium) silently map to `"floodlight"`. `OverlayWebViewCapture` CSS targets per-preset body class selectors (`body.board-floodlight`, `body.board-barlow`, etc.). |
| **Sponsor GL compositing** | `OverlayLayout` carries up to 6 sponsor logo URLs; `StreamCameraEngine` supports three layout modes (single/multi/carousel) and five display modes (static/scroll_top/scroll_bottom/scroll_above_board/scroll_below_board). Carousel auto-advances at configurable interval; scroll modes animate at 30 fps with configurable direction (LTR/RTL/TTB/BTT/Fixed). |
| **Sponsor scroll direction** | `SponsorScrollDirection` object (KMP, iOS, Android) provides `LTR`/`RTL`/`TTB`/`BTT`/`FIXED` constants. Android `StreamCameraEngine` handles both axes: horizontal ticker animates the X position of each sprite; vertical crawl animates the Y position. `FIXED` renders once at the scroll-band position (no timer). Direction is persisted in `OverlayLayoutPrefs.sponsorScrollDirection` and synced via remote companion patch. |
| **Remote companion** | StudioViewModel on both platforms polls the server every 1.5 s for queued remote commands. A paired companion (tablet/second phone) can start/stop broadcast, mute mic, toggle focus lock, and push live sponsor overlay changes without touching the camera phone |
| **Orientation lock** | `OrientationMode` enum (Auto/Landscape/Portrait) on both platforms. The toggle button is a **two-state flip** (Landscape ↔ Portrait based on the current display orientation) — `Auto` is the initial unlocked state (physical auto-rotate) but is never reached via the button, only restored on Studio dismiss. Android: `toggleOrientation(currentlyLandscape: Boolean)` in `StudioViewModel`; `StudioScreen` drives `activity.requestedOrientation`; sensor (`onDeviceOrientationChanged`) is gated — no-op under any lock mode. iOS: `toggleOrientation()` reads `UIWindowScene.interfaceOrientation.isLandscape`; `AppDelegate.orientationLock` + `scene.requestGeometryUpdate` at runtime; `StreamCameraEngine.followDeviceOrientation = false` makes `currentCaptureOrientation()` read the locked interface orientation instead of the physical sensor. Lock is reset to Auto on Studio dismiss so the rest of the app rotates normally. |
| **Device-tiered stream quality** | `DeviceCapabilities.tier()` classifies phones as LOW/MID/HIGH by RAM. HIGH devices (≥6 GB) default to 1080p@4.5Mbps; others default to 720p@2.5Mbps. Overlay refresh cadence, max capture width, and EIS defaults also track the tier. The MID assumption holds until the first `attachView` measures the device — avoids guessing 1080p on a phone that can't sustain it. |
| **Upload-probed Go Live quality** | At Go Live on HIGH-tier devices, `GoLiveQualityPolicy` runs a 2 MB upload probe (8 s timeout) via `CricRelayApiClient.measureUploadMbps()`. Measured ≥ 6 Mbps → 1080p@4.5Mbps; < 6 Mbps → 720p@2.5Mbps; probe unavailable → keep current prepared quality (no downgrade on no evidence). Resolution is fixed once RTMP starts; `BitrateAdapter` handles in-stream dips from there. |
| **RTMP self-heal reconnect** | `StreamReconnectPolicy` arms `cam.setReTries(3)` (via `CameraSession` interface) at Go Live. Mid-broadcast blips emit `EVENT_RECONNECTING` (amber "Connection lost — reconnecting…" banner; broadcast is still live). Retry exhaustion OR auth failure → `endLostStream()` → `EVENT_STREAM_LOST` → `StudioViewModel.onStreamLost()` resets UI + server status. Auth errors (`onAuthError`) bypass all retries — immediate stream-lost with "Stream key rejected. Start the live event in Studio/dashboard first, then try again." Successful reconnect refills the retry budget (`setReTries(MAX_ATTEMPTS)`) so a later outage in the same broadcast still gets the full schedule. Backoff: 1s/2s/4s capped at 8s. `StreamController.onStreamLost()` stops the foreground service without double-stopping the engine. Burn-in failures emit `EVENT_OVERLAY_WARNING` once per key per broadcast (not per frame) so the operator hears about a missing scoreboard during the broadcast. |
| **Adaptive RTMP bitrate** | `BitrateAdapter` (RootEncoder) drives `setVideoBitrateOnFly` in response to `onNewBitrate` callbacks — steps the encode bitrate down when the uplink is congested, then back up when it clears. `StreamStats.congested` / `adapting` are surfaced to the operator via the `StreamStatsBadge` tri-color dot under the LIVE timer. |
| **Local-first studio prefs** | Camera/device settings (stabilization level, keepScreenOn) are stored per-device in `StudioLocalPrefsStore` / iOS `StudioLocalPrefsStore` and never read from the server — a club admin has no business changing this phone's EIS mode. Overlay prefs (board layout, sponsor config, watermark) are cached per match slug; the cache is authoritative for the studio; the server copy is only a seed for a fresh install and the mirror the web dashboard + remote companion read. |
| **Modular-monolith migration** | Strangler pattern toward a Match spine. `cricrelay_core` scoring engine is the first extracted module; 8 parallel tracks running |
| **Gradle module path** | `:feature:x` not `:android:feature:x` — the `android/` directory is **not** part of the Gradle path |
| **Token auth v2** | Bearer org-token (itsdangerous, `issue_stream_token(org)`). `ClubUser` supports multi-member logins per club (admin/member roles). `Organization` is the unit of auth for the mobile API |
| **CricHeroes as relay source** | CricHeroes is now a first-class relay provider alongside Play Cricket — same `RELAY_PROVIDERS` dispatch table, same overlay pipeline, selectable live from the Scoring sheet |
| **PCS BLE archived** | `feature/pcs-ble` removed from both iOS and Android main apps. Protocol decoder + server ingest endpoint kept dormant for possible future reactivation |
| **Android type-safe nav** | Compose Navigation with `@Serializable` route objects; Studio entry uses zoom+fade instead of slide to signal mode shift |
| **Stream management** | Streams can be renamed and deleted from the Home screen (long-press tile → management sheet) on both platforms; `CricRelayApiClient` exposes `renameStream` / `deleteStream` |
| **Thermal management** | Both platforms monitor device thermal state and adapt the overlay capture refresh interval under heat pressure (Android: `PowerManager.OnThermalStatusChangedListener`; iOS: `ProcessInfo.thermalStateDidChangeNotification`). Severe heat surfaces a warning banner; critical heat offers a "Lower quality" button (`stepDownQuality()` — stub pending live-bitrate API) |
| **Mic mute** | New quick toggle on both platforms. Android disables RootEncoder audio; iOS detaches AVCaptureDevice audio from the MediaMixer. Muted state is ephemeral — not persisted across Studio loads |
